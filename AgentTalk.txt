Why a reverse-proxy (recommended best practice)
- Browser-executed code is public — any API key included there is exposed.
- A reverse-proxy (server endpoint that your client calls) keeps keys on the server, allows:
  - Key rotation and rate limiting,
  - Request validation and sanitization,
  - Response filtering and caching,
  - Hiding direct vendor endpoints (reduce CORS surface, add logging).
- In this repo I added that proxy as `/api/generate-image`. The client sends only the prompt; the server attaches the API key and forwards the request to Stability AI.
